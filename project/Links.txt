----------------------------------------------------------------
 QUICK START FOR THE EXAMINER
----------------------------------------------------------------

1. Open the Live Application URL in Chrome, Edge, Firefox or
   Safari. Nothing needs to be installed.

2. Follow the 17-step walkthrough in README.pdf section 4. It
   takes about fifteen minutes and exercises every role, every
   department handover and every safety rule.

3. To change role, sign out at the bottom of the sidebar and
   sign in as another role.

4. There is no reset button in v2.0. Every role now reads and
   writes one shared database, so a reset would clear another
   examiner's work mid-session. The seeded data can be restored
   from the server by the group on request.

5. A session lasts twelve hours. If you are signed out, sign in
   again; nothing is lost, because every action was saved on the
   server when you took it.

6. Every user can change their own password from "Your account",
   reached by selecting their name in the top right. The
   administrator account can create, suspend and reset staff
   accounts from the Staff screen.

----------------------------------------------------------------
 NOTES
----------------------------------------------------------------

- The deployment loads with 28 synthetic patients, 9 staff
  accounts, 6 wards with 34 beds, and open orders, invoices and
  claims, so every screen has content on first visit.

- No real patient data is used anywhere in the system.

- The administrator account is the one to start with if you have
  time for only one: the dashboard, the live activity feed, the
  operations assistant, the staff administration screen and the
  append-only audit log are all reachable from it.

- Worth trying, because it is the point of the system: open any
  patient chart as a doctor or nurse, add an allergy under
  "Allergies and conditions", then try to prescribe a drug of that
  class in a consultation. The prescription is refused and cannot
  be forced through from any screen.

- The system runs on three tiers: the interface on Vercel, the
  API on AWS App Runner, and PostgreSQL on Amazon RDS. The
  database accepts no connection from the internet; only the API
  can reach it.

- The six AI features call Amazon Bedrock and require an internet
  connection. If one reports itself unavailable, the connection is
  down; every other function continues to work. This fallback is
  the designed behaviour and is covered by test case TC-70.

- Blocked actions are the system working as specified: a refused
  prescription, a struck-through appointment slot, a locked
  clinical tab for a non-clinical role, and a refused signature on
  a consultation with no diagnosis are all enforced rules.

- Mobile Money settlement is modelled. The provider request and
  approval sequence is faithful and the records it produces are
  correct, but no real money moves.

- Known limitations are stated in full in README.pdf section 8 and
  Project_Documentation.pdf section 20.

- The first request after a period of inactivity may take a few
  seconds while the API instance wakes. Subsequent requests are
  immediate.
